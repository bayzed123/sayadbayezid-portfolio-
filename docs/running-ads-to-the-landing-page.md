# Running Meta ads to the ecommerce landing page

The page: **https://sayadbayezid.com/ads/fullstack/**

This is the operating manual for that one URL — what to point at it, what to
optimise for, how to check it is working before you spend, and how to read the
numbers afterwards. It is written for the person running the ad account, not
for a developer.

The offer on it: an ecommerce website from **$100**, customisable, built to
whatever the client's requirement is — with four live demos they can click
through before ordering.

> **Why this file is Markdown and `meta-integration.html` is HTML.** This file
> is read on GitHub, which renders Markdown into headings, tables and links.
> The Meta documentation page is opened by URL in a browser, and GitHub Pages
> serves a `.md` file as `text/plain` — a reviewer would get raw asterisks.
> Read on GitHub → Markdown. Opened by URL → HTML. That is the whole rule.

## 0. Before anything: the account has to be allowed to run ads

Ad delivery on this Business account is still gated behind **Business
Verification**. Until that clears, campaigns can be built and saved but will
not spend. Nothing in this document is wrong while you wait — but do not read a
zero-delivery campaign as a broken landing page when the cause is the account.

Check first: **Business Settings → Security Centre → Business Verification.**

## 1. The URL to paste, with tracking attached

Paste this as the **Website URL** on the ad:

```
https://sayadbayezid.com/ads/fullstack/
```

And this as the **URL parameters** field, directly underneath it — not glued
onto the URL above:

```
utm_source=facebook&utm_medium=paid&utm_campaign={{campaign.name}}&utm_content={{ad.name}}&utm_term={{adset.name}}&placement={{placement}}
```

The `{{...}}` parts are Meta's own dynamic parameters. Meta substitutes the
real campaign, ad, ad set and placement names at click time, so you never have
to hand-maintain a URL per ad — and every enquiry that arrives in the inbox
names the ad that paid for it, like this:

```
Came from: utm_source=facebook · utm_medium=paid · utm_campaign=fullstack-sep · utm_content=dashboard-carousel · fbclid=IwAR...
```

That line is generated by the page and attached to the enquiry itself. It
survives the visitor scrolling around and losing the query string, because the
values are captured on arrival and held for the session.

**Do not** add `utm_*` values into the Website URL box as well. You get them
twice, and Meta's own reporting stops matching yours.

## 2. Which objective, and which event to optimise for

| | Choose | Why |
|---|---|---|
| Objective | **Leads** | Not Traffic. Traffic buys you clicks from people who like clicking. |
| Conversion location | **Website** | Not Instant Forms — the whole point is that they see the work first. |
| Performance goal | **Maximise number of conversions** | |
| Conversion event | **Lead** | |
| Attribution | **7-day click, 1-day view** | A decision at this price is not made in the first hour. |

The offer now starts at **$100** (Starter Shop), with Growth at $250 and
Complete Commerce at $450 — and every one of them customisable. That lowers the
barrier a long way: at $100 people will enquire from an ad on impulse, which
means more leads, cheaper leads, and a larger share of them unqualified. Put
the starting price in the ad copy anyway. It costs you the clicks from people
who were never going to pay anything, and you pay for those clicks either way.

### While the pixel is still cold

Meta needs roughly **50 conversions per week per ad set** to leave the learning
phase. At a $100 entry price that is now reachable, but not on day one and not
on a small budget — so do not read a slow start as a broken campaign. Two ways
through it, in order:

1. **Start on `ViewContent`** for the first week or two. It fires far more
   often, so delivery learns something, and on this page it means
   *"reached the pricing and stayed there"* — which is a real signal, not a
   bounce.
2. **Move to `Lead`** once you are seeing leads steadily. Expect delivery to
   wobble for a few days when you switch; that is the learning phase
   restarting, and it settles.

## 3. What the funnel reports, and what it deliberately does not

Tracking is not on the landing page alone. Every page an ad click can reach
loads the same script, `/ads/assets/ads-track.js` — the landing page, the
privacy policy, the terms, and every page of the demo hub at
`demu.sayadbayezid.com`. The middle of a funnel that reports nothing is a hole
in it: whoever browsed the demos and left is the warmest audience the whole
campaign produces, and they are worthless to you if they are invisible.

| Event | When it fires | Sent to the Conversions API? |
|---|---|---|
| `PageView` | On load, on every page in the funnel | Yes (browser only — standard pixel) |
| `ViewContent` | The packages have been on screen for 1.2 continuous seconds | Yes |
| `ViewContent` *(Demo)* | A live demo is opened, from the landing page or the hub | Yes |
| `ContactIntent` *(custom)* | Any "Order Now" button is clicked, anywhere | No — browser only |
| `GalleryCompleted` *(custom)* | Someone scrolls the 12-screen gallery to the end | No — browser only |
| `Lead` | A submission the server **accepted** | Yes |

Every `ContactIntent` names which button was pressed (`hero`, `sticky-bar`,
`tier-starter`, `viewer-bar`, and so on). That tells you which part of the page
is doing the selling, which is not something you can guess.

Three things worth understanding about that table.

**`Lead` means a lead, and nothing else.** It does not fire when the button is
clicked, when the form is opened, or when a submission fails. Clicking is
`ContactIntent`, which is a custom event on purpose — useful for seeing how
many people wanted to order, but kept out of the standard event you optimise
toward so it cannot inflate your lead count.

**There is no `InitiateCheckout` and no `Purchase`.** This page has no cart and
takes no payment, so those events would be fiction. Meta optimises delivery
toward whatever you report — report a fictional event and you buy fictional
buyers, with real money.

**Everything that matters fires twice.** Once in the browser via the Pixel,
once server-side through the Conversions API, both carrying the same
`event_id`. Meta collapses the pair into one event. The browser copy is the one
ad-blockers and iPhone tracking prevention remove; the server copy is the one
that survives them. Without the server copy you lose a real share of
Bangladeshi mobile traffic and never see that you lost it.

### Match quality

The server copy carries `fbp`, `fbc`, and — on `Lead` only — the email and
phone from the form. The email and phone travel over HTTPS to the Worker,
which normalises and SHA-256 hashes them before anything goes to Meta. **Meta
never receives the raw values and cannot.**

`fbc` is the click identifier that ties a conversion back to the exact ad
click. The Pixel normally writes it to a cookie, but only after it loads — and
it is the single most commonly blocked script on the page. So the page builds
`fbc` itself from the `fbclid` in the URL, in Meta's documented
`fb.1.<timestamp>.<fbclid>` shape. This is the biggest match-quality win
available on a paid landing page, and it costs nothing.

## 4. Verify it before you spend a taka

Do this in order. It takes about ten minutes and it is much cheaper than
discovering on day four that nothing was being recorded.

1. **Events Manager → Test Events.** Copy the test code, open the landing page
   with `?fbclid=TEST123` on the end, scroll to the pricing and wait two
   seconds, then submit the form with your own details.
2. You should see **`PageView`, `ViewContent`, `ContactIntent`, `Lead`** —
   each appearing **once**, not twice. Two copies of the same event means
   deduplication is broken; one copy is correct and is what you want to see.
2b. **Then open a demo and come back.** You should see a further `ViewContent`
   in the `Demo` category, and a `PageView` from `demu.sayadbayezid.com`. If
   the hub reports nothing, its copy of the tracking script is not loading and
   the middle of your funnel is dark.
3. Open the `Lead` row. It should show **Browser and Server** on the same
   event, and a match-quality score that mentions email, phone and click ID.
4. **Check the enquiry arrived.** It goes to the same inbox as every
   `/contact.html` submission. If the tracking fired but no enquiry arrived,
   the problem is the API, not the pixel.
5. **Check the server log.** In the admin dashboard, the Conversions API log
   shows the last seven days as `accepted` / `rejected` / `unreachable`.
   `rejected` climbing means Meta is refusing events — that is worth fixing
   before spending, and the reason is recorded per event.

If step 2 shows nothing at all, the usual cause is a browser extension
blocking `connect.facebook.net`. Try it in a private window with extensions
off before concluding anything is wrong with the page.

## 5. Audiences

Start narrow enough to be affordable, not narrow enough to starve.

**Cold — the one to start with**
- Location: Bangladesh. Add Dhaka, Chattogram and Rajshahi as separate ad sets
  only once you have enough budget to learn from each.
- Age 25–50. Below 25 rarely holds the budget for this.
- Detailed targeting: *Small business owners*, *Facebook Page admins*,
  *E-commerce*, *Online shopping*. Then turn **Advantage detailed targeting
  ON** — at this budget, letting Meta widen beats hand-drawn interests.
- Language: no restriction. The page is English, the sales conversation is
  Bangla, and filtering by language here mostly just raises your CPM.

**Warm — build these from day one even if you cannot use them yet**
- Website visitors, 180 days, from the Pixel.
- People who fired `ViewContent` but not `Lead` in 30 days. This is the best
  retargeting audience the page produces: they read the price and did not act.
- Video viewers at 50%, if you run video.
- Page and Instagram engagers, 365 days.

**Lookalike — only once you have the data**
A 1% lookalike of your `Lead` audience needs roughly 100 source leads to be
worth anything. Build it from customers, not leads, once you have them.

**Exclude** everyone who already converted. You are paying to show a first
offer to someone who already took it.

## 6. Creative that matches the page

The page opens on a real storefront screenshot and a promise about money. The
ad has to open on the same thing, or the click bounces on arrival.

**What to use, in order of what usually works here**

1. **The dashboard screenshot** — revenue, gross profit, margin. It is the
   single most arresting image in the whole set because it answers the
   question the buyer actually has. Use the same one the page uses.
1b. **"Open a real one"** — the demos are the strongest asset in this funnel
   and most ads never mention them. An ad whose promise is *click through a
   working shop before you pay anything* is a much easier click than one that
   promises a service.
2. **A carousel**: storefront → dashboard → courier panel → Bangla guide. Each
   card is one line of copy. Every card links to the same URL.
3. **A 15–20 second screen recording**: place an order on the storefront, then
   cut to that order appearing in the dashboard with the profit calculated.
   No narration needed; add Bangla captions burned in, because most of it is
   watched on mute.

**Copy that matches the page**

- Lead with the problem, not the service. *"আপনার শপ কত টাকা লাভ করলো — সেটা
  মাসের শেষে হিসাব করতে হয়?"* beats *"Professional web development services"*
  every time.
- Name the price in the ad. It costs you the clicks from people who were never
  going to pay for a build at this level, which is the point — you pay for
  those clicks either way.
- One call to action: **Learn more**. Not *Sign up*, not *Send message*. The
  page is the pitch.

**Do not** promise a specific income, a guaranteed ranking, or a fixed number
of sales. Beyond being untrue, Meta rejects ads that imply guaranteed business
outcomes.

## 7. The ad policy checklist for this page

Run through this once before submitting. A rejection costs you review time,
and repeated rejections cost account standing.

- [x] **Privacy policy is linked** and reachable from the page — required
      whenever a page collects contact details.
- [x] **Consent is explicit.** The form will not submit without the box
      ticked, and the box names what the details are used for.
- [x] **The page matches the ad.** No bait. If the ad names a price, it is
      the same price the page names. The page quotes **$450** and no taka
      figure, deliberately — a converted number on a live page goes stale
      silently. If you name taka in the ad copy, you are responsible for
      keeping it current.
- [x] **No fabricated proof.** The screenshots are captioned as system
      calculations on a demonstration dataset, not a client's trading figures.
      That caption is not decoration; leave it there.
- [x] **Working on a phone**, no horizontal scrolling, form usable one-handed.
- [x] **No login wall** in front of the offer.
- [ ] **Business Verification complete** — see section 0.

## 8. Reading the results

Give it **seven days minimum** before judging anything. Ad delivery spends the
first days learning, and a verdict on day two is a verdict on noise.

| What you see | What it usually means | What to change |
|---|---|---|
| High CTR, no `ViewContent` | The page loads slowly, or the ad promised something else | Check the ad image against the hero; check the page on 3G |
| `ViewContent` high, `Lead` near zero | They read the price and stopped | The price is the objection. Test a starting-tier offer, not a cheaper build |
| `Lead` arrives but nobody replies to you | The leads are not real buyers | Narrow the audience; put the price in the ad |
| CPM rising, everything else flat | Audience fatigue | New creative, same targeting. Creative fatigues long before audiences do |
| `ContactIntent` high, `Lead` low | They click Order and abandon the form | The form is too long, or the consent line is scaring them |

**The number that actually matters** is cost per *qualified* lead — a lead you
would take a call with — not cost per lead. On a build at this price, one
qualified lead a week, at a few thousand taka of ad spend, is a working
campaign.
Judge it against the value of a build, not against the cost of a click.

## 9. When you change the page

The landing page has a test suite. Run it after any edit, before deploying,
because the tracking is the part that fails silently:

```bash
python3 -m http.server 8901
CHROMIUM_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome \
  node tests/ads-landing.mjs
```

It stubs the pixel and intercepts both API calls, so nothing reaches Meta and
no enquiry reaches the inbox. It checks that the browser and server copies
share an event ID, that `ViewContent` needs a real dwell, that `fbc` is built
correctly from `fbclid`, that the form refuses incomplete and unconsented
submissions, that a complete enquiry carries the phone, scope, website and
campaign, and that a hostile error message from the server cannot execute
script on the page.
